Hooks esenciales en React: useState, useEffect y ciclo de sincronización

Gestión de memoria local inmutable con useState, sincronización con sistemas externos mediante useEffect, limpieza de recursos y reglas de uso de hooks.

Propósito de los Hooks en componentes funcionales

En React y sus componentes funcionales, las funciones se ejecutan nuevamente cada vez que la interfaz necesita actualizarse, lo que significa que las variables locales declaradas con let o const dentro del cuerpo de la función se reinician en cada renderizado. Los Hooks son funciones especiales proporcionadas por React que permiten a los componentes funcionales engancharse al motor interno de estado y ciclo de sincronización sin necesidad de escribir clases, manteniendo la coherencia con la arquitectura de componentes en el frontend.

Gestión de estado local e inmutabilidad con useState

El hook useState declara una variable de estado que React preserva entre renderizados sucesivos. Recibe como argumento el valor inicial y devuelve un arreglo de dos posiciones: el valor actual del estado y una función actualizadora (setter). Invocar la función actualizadora con un valor distinto programa un nuevo renderizado del componente.

Cuando el nuevo estado depende directamente del valor inmediatamente anterior —por ejemplo, en contadores o interruptores— resulta recomendable pasar una función de actualización al setter para evitar lecturas obsoletas si ocurren múltiples actualizaciones en lote:

import { useState } from 'react';

function ControlCantidad() {
  const [unidades, setUnidades] = useState(1);

  function duplicarUnidades() {
    setUnidades((previas) => previas * 2);
  }

  return (
    <div>
      <p>Unidades seleccionadas: {unidades}</p>
      <button type="button" onClick={duplicarUnidades}>Duplicar</button>
    </div>
  );
}

Un principio crítico al trabajar con objetos y arreglos en useState es la inmutabilidad. React compara la referencia en memoria del estado anterior y el nuevo mediante Object.is(). Si se muta directamente una propiedad de un objeto o se usa array.push() sobre la referencia existente, React detectará que la referencia no ha cambiado y omitirá el renderizado. Siempre deben crearse copias nuevas mediante el operador de propagación (...) o métodos inmutables como map y filter:

const [perfil, setPerfil] = useState({ nombre: 'Ana', activo: true });

// Correcto: crea un nuevo objeto preservando las demás propiedades
function alternarEstado() {
  setPerfil((actual) => ({ ...actual, activo: !actual.activo }));
}

Sincronización con sistemas externos mediante useEffect

Mientras el renderizado debe permanecer libre de efectos secundarios, las aplicaciones reales necesitan interactuar con sistemas externos a React: suscribirse a eventos globales del navegador, manipular temporizadores, sincronizar el título del documento o realizar peticiones HTTP hacia una API. El hook useEffect permite ejecutar ese código de sincronización después de que React ha confirmado los cambios en el DOM.

useEffect acepta dos argumentos: una función con la lógica del efecto y un arreglo opcional de dependencias que determina cuándo debe volver a ejecutarse dicha sincronización:

  • Arreglo con dependencias [a, b]: El efecto se ejecuta tras el montaje inicial y cada vez que cualquiera de los valores listados cambie respecto al renderizado anterior.
  • Arreglo vacío []: El efecto no depende de ningún valor reactivo, por lo que se ejecuta únicamente una vez cuando el componente se monta en pantalla.
  • Sin arreglo de dependencias: El efecto se ejecuta después de cada renderizado del componente, un comportamiento poco frecuente que debe emplearse con cautela.

Funciones de limpieza y prevención de fugas de memoria

Muchos efectos establecen recursos persistentes —como suscripciones a WebSockets, escuchadores de eventos con addEventListener, intervalos con setInterval o peticiones de red cancelables mediante AbortController—. Si el componente se desmonta de la pantalla o el efecto vuelve a ejecutarse con nuevas dependencias sin cerrar el recurso previo, se producen fugas de memoria o condiciones de carrera.

Para evitarlo, la función pasada a useEffect puede retornar una función de limpieza (cleanup function). React invoca esta función de limpieza antes de ejecutar el efecto nuevamente y justo antes de desmontar el componente:

import { useState, useEffect } from 'react';

function BuscadorUsuarios({ consulta }) {
  const [resultados, setResultados] = useState([]);

  useEffect(() => {
    if (!consulta.trim()) {
      setResultados([]);
      return;
    }

    const controlador = new AbortController();

    async function cargarUsuarios() {
      try {
        const respuesta = await fetch(`/api/usuarios?q=${encodeURIComponent(consulta)}`, {
          signal: controlador.signal
        });
        const datos = await respuesta.json();
        setResultados(datos);
      } catch (error) {
        if (error.name !== 'AbortError') {
          console.error('Error al consultar usuarios:', error);
        }
      }
    }

    cargarUsuarios();

    return () => {
      controlador.abort();
    };
  }, [consulta]);

  return (
    <ul>
      {resultados.map((u) => (
        <li key={u.id}>{u.nombre}</li>
      ))}
    </ul>
  );
}

Reglas fundamentales de los Hooks

Internamente, React asocia cada llamada a un hook con el componente mediante el orden exacto en que se invocan durante cada renderizado, almacenándolos en una lista enlazada interna. Para que este mecanismo funcione sin corromperse, deben respetarse dos reglas estrictas:

  1. Invocar hooks únicamente en el nivel superior: Nunca deben llamarse dentro de condicionales (if), bucles (for, while) ni funciones anidadas.
  2. Invocar hooks únicamente desde funciones de React: Solo pueden ejecutarse dentro de componentes funcionales de React o dentro de hooks personalizados.

Asimismo, no conviene abusar de useEffect para calcular valores derivados del estado o de las propiedades (por ejemplo, concatenar nombre y apellido); esos valores deben calcularse directamente durante el renderizado.
