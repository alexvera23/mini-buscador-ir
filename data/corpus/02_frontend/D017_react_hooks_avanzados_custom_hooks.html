Hooks avanzados y creación de Custom Hooks reutilizables

Transiciones de estado estructuradas con useReducer, referencias mutables con useRef, memoización con useMemo y useCallback, y extracción de Custom Hooks.

Más allá del estado básico en React

A medida que los componentes funcionales de React evolucionan dentro de la arquitectura frontend, el uso exclusivo de useState y useEffect puede volverse verboso cuando múltiples variables de estado cambian de forma coordinada, cuando se requiere acceder imperativamente a nodos del DOM o cuando la misma lógica de suscripción se repite en distintas vistas.

Estado estructurado con useReducer

El hook useReducer constituye una alternativa a useState diseñada para gestionar estados complejos con múltiples subvalores o transiciones donde el siguiente estado depende de reglas de negocio bien definidas. Este patrón concentra toda la lógica de actualización en una función pura llamada reducer que recibe el estado actual y un objeto action descriptivo, devolviendo el nuevo estado inmutable.

import { useReducer } from 'react';

const estadoInicial = { cargando: false, datos: null, error: null };

function peticionReducer(estado, accion) {
  switch (accion.tipo) {
    case 'INICIAR':
      return { cargando: true, datos: null, error: null };
    case 'EXITO':
      return { cargando: false, datos: accion.carga, error: null };
    case 'FALLO':
      return { cargando: false, datos: null, error: accion.mensaje };
    default:
      return estado;
  }
}

function VistaReporte() {
  const [estado, despachar] = useReducer(peticionReducer, estadoInicial);
  // despachar({ tipo: 'INICIAR' }) dispara una transición predecible y aislada
}

Separar las transiciones de estado en un reducer facilita las pruebas unitarias, ya que la función puede probarse con entradas y salidas simples sin necesidad de montar ningún componente en un navegador simulado.

Referencias persistentes sin re-renderizado con useRef

El hook useRef devuelve un objeto mutable con una única propiedad current que persiste durante todo el ciclo de vida del componente. A diferencia de useState, modificar ref.current no provoca un nuevo renderizado del componente.

Sus dos casos de uso principales son:

  • Acceso imperativo a elementos del DOM: Vincular ref={miRef} a una etiqueta JSX permite enfocar un campo de texto (inputRef.current.focus()), medir dimensiones o controlar la reproducción de elementos multimedia.
  • Almacenamiento de valores internos auxiliares: Guardar identificadores de temporizadores (setTimeout), contadores de renderizados o el valor previo de una propiedad sin afectar la visualización.

Memoización selectiva con useMemo y useCallback

En JavaScript, cada vez que un componente se vuelve a renderizar, las funciones y objetos declarados en su interior se crean nuevamente con nuevas referencias en memoria. React proporciona dos hooks para preservar valores entre renderizados mientras sus dependencias no cambien:

  • useMemo(() => calculoCostoso(a, b), [a, b]): Almacena en caché el resultado de una operación computacionalmente exigente (como filtrar u ordenar miles de registros en el cliente) para evitar recalcularlo cuando cambien otras partes no relacionadas del componente.
  • useCallback((id) => manejarSeleccion(id), [dependencia]): Preserva la misma referencia de función entre renderizados. Resulta útil cuando dicha función se pasa como propiedad a un componente hijo envuelto en React.memo o cuando actúa como dependencia dentro de un useEffect.

Conviene aplicar ambos hooks de manera medida: memoizar cálculos triviales añade sobrecarga de memoria y comparación de dependencias sin aportar mejoras reales de rendimiento.

Diseño de Custom Hooks reutilizables

La verdadera potencia compositiva de React reside en la creación de Custom Hooks (hooks personalizados). Un Custom Hook es una función convencional de JavaScript cuyo nombre comienza obligatoriamente con el prefijo use y que invoca en su interior otros hooks de React para encapsular lógica con estado reutilizable.

Cada componente que invoca un Custom Hook obtiene su propia instancia aislada de estado y efectos; lo que se comparte es la lógica de comportamiento, no los datos en sí. Por ejemplo, al consumir servicios web que intercambian datos estructurados en formato JSON sobre la infraestructura de la World Wide Web, es habitual extraer un hook genérico de consulta:

import { useState, useEffect } from 'react';

export function useConsultaJson(url) {
  const [datos, setDatos] = useState(null);
  const [cargando, setCargando] = useState(true);
  const [error, setError] = useState(null);

  useEffect(() => {
    const controlador = new AbortController();
    setCargando(true);

    fetch(url, { signal: controlador.signal })
      .then((res) => {
        if (!res.ok) throw new Error(`Error HTTP ${res.status}`);
        return res.json();
      })
      .then((json) => {
        setDatos(json);
        setError(null);
      })
      .catch((err) => {
        if (err.name !== 'AbortError') setError(err.message);
      })
      .finally(() => setCargando(false));

    return () => controlador.abort();
  }, [url]);

  return { datos, cargando, error };
}

Al extraer detalles de red, temporizadores o suscripciones en Custom Hooks bien delimitados, los componentes visuales recuperan su claridad declarativa.
