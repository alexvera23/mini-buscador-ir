Introducción a React, JSX y composición declarativa de interfaces

Fundamentos de la biblioteca de interfaces de usuario, sintaxis JSX, componentes funcionales y transmisión de datos mediante propiedades inmutables.

Filosofía declarativa de React

React es una biblioteca de JavaScript especializada en la construcción de interfaces de usuario mediante piezas modulares e independientes. A diferencia de los enfoques imperativos tradicionales —donde el código busca nodos específicos en el DOM y ejecuta instrucciones secuenciales para añadir clases, modificar texto o insertar elementos—, React adopta un paradigma estrictamente declarativo dentro de los principios de la arquitectura de componentes en el frontend.

En React, el desarrollador define qué estructura visual corresponde a cada posible estado de la aplicación. Cuando los datos cambian, React vuelve a ejecutar los componentes afectados para obtener una nueva descripción de la interfaz, calcula las diferencias respecto al renderizado previo mediante su árbol de reconciliación y actualiza únicamente los nodos estrictamente necesarios en el navegador. Este diseño permite razonar sobre cada vista como una proyección determinista de los datos vigentes en un instante dado.

Sintaxis JSX y su transformación a JavaScript

Para describir estructuras de interfaz de manera legible, React utiliza JSX (JavaScript XML), una extensión de sintaxis que permite escribir etiquetas similares a HTML directamente dentro de archivos JavaScript o TypeScript. JSX no es interpretado de forma nativa por los navegadores; durante la fase de compilación, herramientas como Babel, SWC o esbuild transforman cada etiqueta JSX en llamadas a funciones estándar de JavaScript que crean objetos descriptores denominados elementos de React.

// Código escrito con sintaxis JSX
function SaludoUsuario({ nombre, rol }) {
  return (
    <section className="tarjeta-perfil">
      <h2>Hola, {nombre}</h2>
      <p>Rol asignado: {rol.toUpperCase()}</p>
    </section>
  );
}

Debido a que JSX se compila a expresiones de JavaScript, existen reglas sintácticas esenciales que lo distinguen del HTML tradicional:

  • Expresiones entre llaves: Cualquier expresión válida de JavaScript —variables, llamadas a funciones, operadores ternarios— puede incrustarse dentro del marcado encerrándola entre llaves { }.
  • Atributos en camelCase: Las propiedades siguen la convención de nombres de las APIs del DOM en JavaScript, por lo que se escribe className en lugar de class, htmlFor en lugar de for y onClick para eventos.
  • Cierre explícito de etiquetas: Todas las etiquetas deben cerrarse correctamente, incluidas las etiquetas vacías como <img /> o <input />.
  • Elemento raíz único: Una expresión JSX debe devolver un único nodo contenedor. Cuando no se desea añadir un <div> innecesario al DOM, se emplean fragmentos mediante <>...</>.

Componentes funcionales y propiedades (Props)

En el desarrollo moderno con React, los componentes se definen como funciones de JavaScript cuyo nombre comienza con letra mayúscula para que el compilador las distinga de las etiquetas HTML nativas. Estas funciones reciben un único objeto como argumento, conocido convencionalmente como props (abreviatura de propiedades), y retornan elementos JSX.

Las props constituyen el canal de comunicación descendente entre un componente padre y sus hijos. Una regla fundamental de React establece que las props son estrictamente de solo lectura: un componente nunca debe modificar el objeto de propiedades que recibe. Si se requiere alterar un dato, el componente propietario debe actualizar su propio estado y volver a renderizar al hijo con los nuevos valores.

function InsigniaEstado({ activo, etiqueta }) {
  const claseEstado = activo ? 'estado-activo' : 'estado-inactivo';
  return <span className={claseEstado}>{etiqueta}</span>;
}

function FilaServicio({ nombre, enLinea }) {
  return (
    <div className="fila-servicio">
      <span>{nombre}</span>
      <InsigniaEstado
        activo={enLinea}
        etiqueta={enLinea ? 'Operativo' : 'Sin conexión'}
      />
    </div>
  );
}

Composición con children y renderizado dinámico

En lugar de recurrir a la herencia de clases para especializar interfaces, React favorece la composición. La propiedad especial children permite que un componente contenedor reciba elementos arbitrarios anidados entre sus etiquetas de apertura y cierre sin conocer de antemano qué contenido renderizará en su interior. Este patrón resulta ideal para construir paneles, ventanas modales, barras laterales o contenedores de diseño.

function PanelContenedor({ titulo, children }) {
  return (
    <aside className="panel">
      <header><h3>{titulo}</h3></header>
      <div className="panel-contenido">{children}</div>
    </aside>
  );
}

Para transformar colecciones de datos en listas de elementos visuales, se utiliza habitualmente el método Array.prototype.map() dentro de JSX. Cada elemento generado dinámicamente dentro de una lista debe incluir una propiedad especial llamada key con un identificador único y estable entre renderizados, como el identificador de base de datos del registro. La propiedad key permite al algoritmo de reconciliación identificar qué elementos fueron añadidos, eliminados o reordenados sin destruir ni recrear innecesariamente los nodos existentes.

function ListaCategorias({ categorias }) {
  if (categorias.length === 0) {
    return <p>No existen categorías registradas.</p>;
  }

  return (
    <ul>
      {categorias.map((categoria) => (
        <li key={categoria.id}>{categoria.nombre}</li>
      ))}
    </ul>
  );
}

Buenas prácticas y evolución hacia el manejo de estado

Para mantener componentes predecibles y fáciles de probar, conviene diseñarlos como funciones puras respecto a sus entradas: ante las mismas props y el mismo estado interno, deben producir exactamente la misma salida JSX sin alterar variables externas durante la fase de renderizado.

Cuando la interfaz requiere interactividad dinámica, almacenamiento de valores locales o sincronización con APIs externas, los componentes funcionales incorporan mecanismos específicos del ecosistema React:

  • Para gestionar memoria local y efectos secundarios, consulta hooks esenciales en React: useState, useEffect y ciclo de sincronización.
  • Para encapsular comportamientos complejos y optimizar cálculos, revisa hooks avanzados y creación de Custom Hooks reutilizables.
  • Para compartir información transversal entre múltiples niveles del árbol sin pasar propiedades manualmente, explora React Context API y comparación con librerías de estado global.
