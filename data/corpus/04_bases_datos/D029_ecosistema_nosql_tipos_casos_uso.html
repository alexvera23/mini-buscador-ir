Panorama de bases de datos NoSQL: documental, clave-valor, columnar y grafos

Motivaciones del movimiento NoSQL, compromisos del teorema CAP en sistemas distribuidos, clasificación de las cuatro familias principales y criterios frente al modelo relacional.

Motivaciones frente al modelo relacional clásico

El término NoSQL (Not Only SQL) agrupa un conjunto diverso de sistemas de gestión de datos diseñados para resolver escenarios donde las bases de datos relacionales tradicionales enfrentan fricciones estructurales:

  • Escalado horizontal nativo (Sharding): Particionar tablas normalizadas con múltiples claves foráneas a través de decenas de servidores distribuidos penaliza las operaciones JOIN por red. Los sistemas NoSQL priorizan modelos de datos auto-contenidos fáciles de distribuir por clave de partición.
  • Evolución ágil y esquemas flexibles: En dominios con atributos heterogéneos o cambiantes —como catálogos de comercio electrónico con especificaciones variables por categoría—, exigir migraciones rígidas de columnas puede ralentizar la entrega de producto.
  • Latencia ultra baja y alto caudal de escritura: Cargas como telemetría de sensores, sesiones efímeras o contadores en tiempo real requieren estructuras optimizadas en memoria o escritura secuencial en disco.

El Teorema CAP y la consistencia eventual

Al distribuir datos entre múltiples nodos conectados por red, el Teorema CAP formulado por Eric Brewer establece que, ante una partición de red (P, pérdida o retraso de mensajes entre nodos), un sistema distribuido debe elegir entre garantizar:

  • Consistencia fuerte (C - Consistency): Toda lectura recibe la escritura más reciente o un error, rechazando operaciones si no es posible sincronizar los nodos.
  • Disponibilidad (A - Availability): Cada petición recibe una respuesta no errónea, incluso si algunos nodos no han recibido aún las últimas réplicas de escritura.

Dado que las particiones de red son inevitables en sistemas distribuidos reales, muchos motores NoSQL optan por modelos BASE (Basically Available, Soft state, Eventual consistency), garantizando alta disponibilidad y convergencia gradual de todas las réplicas cuando cesa la interrupción de red.

Las cuatro familias principales de bases de datos NoSQL

NoSQL no es una tecnología única, sino cuatro paradigmas especializados según la estructura de acceso predominante:

  • Bases de datos documentales (ej. MongoDB, Couchbase): Almacenan registros como documentos estructurados autocontenidos (generalmente BSON o JSON) agrupados en colecciones. Permiten anidar subdocumentos y arreglos directamente dentro de la entidad principal, evitando reconstruir objetos complejos mediante múltiples uniones.
  • Almacenes clave-valor (ej. Redis, Amazon DynamoDB): Funcionan como diccionarios distribuidos de altísimo rendimiento donde cada valor opaco o estructura en memoria se recupera en tiempo constante $O(1)$ mediante su clave única. Son el estándar de facto para cachés distribuidas, gestión de sesiones, colas ligeras y limitadores de tasa (rate limiting).
  • Bases de datos orientadas a familias de columnas (ej. Apache Cassandra, ScyllaDB): Organizan datos por filas identificadas con claves de partición y agrupamiento, optimizadas para ingestión masiva de escrituras distribuida en múltiples centros de datos, series temporales y analítica a gran escala.
  • Bases de datos de grafos (ej. Neo4j): Representan entidades como nodos y sus vínculos como aristas con propiedades explícitas. Sobresalen en consultas de recorrido profundo —como redes sociales, motores de recomendación, rutas logísticas y detección de fraude— donde los JOIN recursivos en SQL se vuelven prohibitivos.

Persistencia políglota en aplicaciones modernas

Lejos de ser excluyentes, las bases relacionales y NoSQL suelen coexistir bajo el enfoque de persistencia políglota: utilizar PostgreSQL o MySQL como fuente principal de verdad transaccional para pedidos, facturación y usuarios, complementándolo con Redis para caché de baja latencia y sesiones, o un motor documental para registros de eventos semiestructurados.
