Fundamentos de bases de datos relacionales y lenguaje SQL

Guía central sobre el modelo relacional propuesto por Edgar F. Codd, integridad referencial, transacciones ACID, lenguaje declarativo SQL y panorama de motores de persistencia.

Persistencia estructurada y el modelo relacional

Toda aplicación web con estado necesita almacenar información de forma duradera más allá del ciclo de vida en memoria de los servidores backend. Formulado matemáticamente por Edgar F. Codd en 1970, el modelo relacional organiza los datos en relaciones bidimensionales denominadas tablas, donde cada fila (o tupla) representa una instancia única de una entidad y cada columna (o atributo) define una propiedad con un dominio de tipo estricto.

La fortaleza principal de las bases de datos relacionales radica en delegar la integridad estructural y transaccional al propio motor gestor (SGBD), evitando que errores en el código de aplicación corrompan el estado del negocio:

  • Clave primaria (Primary Key - PK): Columna o conjunto de columnas que identifica de manera unívoca y no nula cada registro dentro de una tabla (por ejemplo, usuario_id).
  • Clave foránea (Foreign Key - FK): Columna que referencia la clave primaria de otra tabla, estableciendo un vínculo verificado por el motor para impedir registros huérfanos.
  • Restricciones declarativas (Constraints): Reglas como NOT NULL, UNIQUE y CHECK que rechazan automáticamente cualquier escritura que viole las invariantes definidas en el esquema.

Propiedades ACID y garantías transaccionales

Cuando múltiples usuarios interactúan simultáneamente con una aplicación web, las operaciones de escritura deben agruparse en transacciones lógicas que cumplan cuatro garantías fundamentales conocidas como ACID:

  • Atomicidad (Atomicity): Todas las operaciones dentro de la transacción se ejecutan por completo (COMMIT) o ninguna tiene efecto (ROLLBACK), evitando estados intermedios inconsistentes como descontar saldo sin acreditar el destino.
  • Consistencia (Consistency): Cada transacción lleva la base de datos de un estado válido a otro estado válido respetando todas las restricciones e integridad referencial.
  • Aislamiento (Isolation): Las transacciones concurrentes se ejecutan sin interferir entre sí, evitando lecturas sucias o actualizaciones perdidas según el nivel de aislamiento configurado.
  • Durabilidad (Durability): Una vez confirmada una transacción, sus cambios persisten en almacenamiento no volátil (mediante registros de escritura anticipada como WAL) incluso ante fallos eléctricos o reinicios del sistema.

SQL como lenguaje declarativo de consulta y definición

Para interactuar con motores relacionales se utiliza SQL (Structured Query Language). A diferencia de los lenguajes imperativos donde se especifica paso a paso cómo recorrer estructuras de datos, SQL es un lenguaje declarativo: el desarrollador describe qué conjunto de resultados desea obtener y el optimizador de consultas del motor determina el plan de ejecución más eficiente.

CREATE TABLE clientes (
  id SERIAL PRIMARY KEY,
  correo VARCHAR(150) NOT NULL UNIQUE,
  activo BOOLEAN NOT NULL DEFAULT TRUE,
  creado_en TIMESTAMP NOT NULL DEFAULT CURRENT_TIMESTAMP
);

SELECT id, correo
FROM clientes
WHERE activo = TRUE
ORDER BY creado_en DESC;

El estándar SQL se divide habitualmente en subconjuntos funcionales: DDL (Data Definition Language: CREATE, ALTER, DROP) para definir estructuras; DML (Data Manipulation Language: SELECT, INSERT, UPDATE, DELETE) para consultar y modificar datos; y TCL (Transaction Control Language: BEGIN, COMMIT, ROLLBACK) para delimitar transacciones.

Ecosistema de bases de datos y decisiones arquitectónicas

Elegir y diseñar la capa de persistencia es una de las decisiones con mayor impacto dentro de la arquitectura de software y atributos de calidad, ya que migrar esquemas y volúmenes masivos de datos en producción conlleva costos elevados. A partir de estos fundamentos, el estudio de las bases de datos se ramifica en áreas especializadas:

  • Para dominar consultas relacionales complejas entre múltiples entidades, revisa combinación de tablas con JOIN y funciones de agregación, GROUP BY y filtrado con HAVING.
  • Para evaluar los motores relacionales de código abierto más utilizados en la web, consulta PostgreSQL y MySQL: arquitectura, diferencias clave y criterios de elección.
  • Para estructurar esquemas limpios desde los requisitos del dominio, explora modelado de datos para aplicaciones web: del modelo conceptual al esquema físico.
  • Para conectar el código orientado a objetos o funcional con el motor de almacenamiento, analiza ORMs, ODMs y niveles de abstracción en el acceso a datos.
  • Para comprender alternativas orientadas a documentos, clave-valor o grafos, revisa el panorama de bases de datos NoSQL.
